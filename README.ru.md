# Что нагружает компьютер

[English](README.md) · [Лицензия MIT](LICENSE)

Прототип плагина ChatGPT и локального диагностического агента для macOS и Windows.
Он делает короткий замер ресурсов, показывает наиболее затратные процессы и объясняет,
что стоит проверить. Завершение приложения требует отдельного подтверждения на компьютере.

Версия 0.1.4 подготовлена для открытой публикации под лицензией MIT. Это независимый проект;
он не является официальным продуктом OpenAI и не опубликован в каталоге ChatGPT.
На macOS выполнена живая диагностика; реальный запуск на Windows ещё нужен.

## Быстрый запуск

Нужны Node.js 20+ и Python 3.9+ (на Windows — Python Launcher `py`). Запускайте от обычного
пользователя, без sudo и прав администратора.

- macOS: откройте `Start-macOS.command`.
- Windows: распакуйте весь архив в обычную папку и откройте `Start-Windows.cmd`.
- В обоих случаях откроется локальная панель <http://127.0.0.1:8798>.
- Нажмите «Проверить сейчас». Первый запуск устанавливает зависимости из npm/PyPI в папку проекта.
- Терминал оставьте открытым, пока пользуетесь агентом. Для остановки самого агента — Ctrl+C.

Если файл запуска macOS скачан без права на исполнение, перед открытием выполните
из папки проекта `chmod +x Start-macOS.command`.

Ручной запуск из папки проекта:

```sh
npm run setup
npm start
```

Без подключения к ChatGPT панель уже работает: можно скачать JSON-отчёт и приложить его
к своему чату для анализа. В браузере агента происходит только локальная обработка;
передача отчёта в ChatGPT — отдельное действие пользователя.

## Что проверяется

| Показатель | Как трактовать |
| --- | --- |
| CPU компьютера | Среднее и 2–10 отдельных замеров; 100% означает все логические ядра |
| CPU процесса | 100% означает одно ядро; может превышать 100%; есть также доля всего CPU |
| RAM | Доступная память, процент использования и изменение занятого swap |
| Процессы | Лидеры по CPU и памяти; в первом замере до 25 процессов |
| Диск | Свободное место системного диска, общий поток чтения/записи |
| Диск процесса | Только если ОС и права позволяют; на macOS может быть недоступен |
| Сеть | Общая скорость приёма/передачи; сетевые адреса не собираются |

Высокая нагрузка — повод проверить полезную работу и повторить замер, а не диагноз вируса.
Плагин не измеряет GPU, температуру, нативное давление памяти macOS или здоровье диска,
не читает файлы и не выполняет антивирусную проверку. RSS разных процессов может включать
одну общую память; эти значения нельзя складывать как точное использование RAM.
Процессы, появившиеся во время замера, будут видны при следующем измерении.

## Закрытие приложений

1. Сделайте диагностику.
2. Для допустимого процесса выберите «Запросить закрытие» или явно попросите это в чате.
3. В локальной панели на компьютере введите точное имя приложения и подтвердите, что сохранили работу.
4. Агент повторно сверит PID, время создания, имя, исполняемый файл, владельца и правила защиты.
5. В macOS отправляется только SIGTERM; в Windows — WM_CLOSE видимому окну. Если приложение
   не закрылось за три секунды, принудительного завершения не будет.
6. После результата `exited` сделайте новый замер, чтобы проверить эффект. Это результат для
   выбранного процесса; отсутствие перезапуска приложения или выхода всех его помощников не гарантируется.

Первая версия допускает запрос закрытия только для точных известных основных исполняемых
файлов VLC, IINA и Spotify в macOS, VLC и Spotify в Windows. Системные, чужие, неизвестные
процессы, 1С, базы данных, резервное копирование, синхронизация, средства доступа и сам агент
через плагин завершить нельзя. Для остальных приложений предлагается обычное закрытие после сохранения работы.
SIGTERM на macOS тоже может потерять несохранённое состояние — это явно показано перед подтверждением.

Запрос действует 60 секунд, замер — 120 секунд. Запрос нельзя использовать повторно.
Выполнение остановки вообще не выставлено как MCP-инструмент.

## Подключение к ChatGPT

Архитектура `vanilla-widget`: сервер MCP на Node.js, простой HTML-интерфейс по стандарту
MCP Apps, локальный агент на Python/psutil. Образец подключения ресурсов и транспорта взят
из [OpenAI MCP App Basics](https://github.com/openai/openai-apps-sdk-examples/tree/main/mcp_app_basics_node)
и [официального quickstart](https://developers.openai.com/apps-sdk/quickstart), без остальных демонстрационных инструментов.

| Инструмент | Действие |
| --- | --- |
| `diagnose_computer` | Свежий замер; только чтение |
| `show_diagnosis` | Показывает существующий замер в чате |
| `prepare_process_stop` | Создаёт запрос локального подтверждения; процесс продолжает работать |
| `get_stop_status` | Читает статус запроса и проверенный результат |

### Частный сервер через Secure MCP Tunnel

Это предпочтительный вариант для облачного ChatGPT. Согласно
[официальной инструкции OpenAI](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels),
Secure MCP Tunnel соединяет ChatGPT с частным сервером без публичного входящего порта.
Для него требуются доступ к туннелям, `tunnel_id`, ключ для `tunnel-client` и связь с нужным
workspace. Их доступность зависит от вашего аккаунта; этот проект их не создаёт и не запрашивает.

1. Запустите агент (`npm start`).
2. По официальной инструкции установите и настройте `tunnel-client` на том компьютере,
   который диагностируется. Частный MCP-адрес: `http://127.0.0.1:8797/mcp`.
3. Если HTTP-профиль туннеля меняет Host или добавляет Origin/forwarded-заголовки,
   используйте его stdio-режим: команда `node`, аргументы — абсолютный путь к
   `server/main.mjs` и `--stdio`. Тогда предварительно остановите `npm start`, поскольку
   stdio-сервер сам запускает локальную панель и занимает те же порты.
4. В ChatGPT включите Developer mode в Settings → Security and login, если он доступен.
5. Откройте [ChatGPT Plugins](https://chatgpt.com/plugins), нажмите плюс, выберите Connection → Tunnel,
   укажите доступный туннель и проверьте список из четырёх инструментов.
6. Добавьте подключение в новый чат и попросите: «Проверь, что нагружает мой компьютер».
7. После изменений инструментов обновите подключение через Refresh.

Точные актуальные команды и параметры профиля `tunnel-client` берите из документации
вашей версии: этот проект не содержит выдуманного формата профиля или ключей.
Для публичного каталога нужен другой вариант размещения с публичным HTTPS, авторизацией
и привязкой к отдельным агентам. Текущий прототип для такого размещения не готов.

### Локальный плагин в поддерживаемом desktop-клиенте

В корне есть portable `plugin.json`, `mcp.json` и навык `skills/computer-load/SKILL.md`.
Repo marketplace подготовлен в `.agents/plugins/marketplace.json`. Подготовьте зависимости
именно в папке, из которой будет загружаться плагин. Запущенный отдельно `npm start`
нужно остановить до запуска stdio-плагина: два агента одновременно занимают одни порты.
В Codex на этом Mac установка и обнаружение инструментов проверены 3 октября 2026:

```sh
codex plugin marketplace add /absolute/path/to/computer-load-chatgpt --json
codex plugin add computer-load@computer-load-local --json
```

Установка копирует подготовленный проект в кеш Codex. На macOS копировщик может
пропустить ссылки на интерпретатор `.venv`; в этом случае агент запускает изолированный
`python3` и подключает только зависимости из соответствующей версии Python внутри пакета.
Если версия Python изменилась, подготовьте зависимости заново и переустановите плагин.
Для нового чата: «Проверь нагрузку компьютера через computer-load».
Виджет проверен во встроенном браузере Codex в изолированном тестовом iframe: живые
данные, сортировка, повторный замер, ошибки и восстановление. Отображение именно в ленте
desktop-чата пока не проверено: в текущем чате новые инструменты отсутствуют.
Формат пакета основан на [Package your plugin](https://developers.openai.com/plugins/build/plugins).

## Данные и границы доступа

- Сбор только по запросу; непрерывного сканирования и автозапуска нет.
- В отчёт уходят имена процессов, PID и показатели ресурсов. Ни аргументы команд, ни
  содержимое файлов, ни история браузера, ни hostname, ни сетевые адреса не собираются.
- Полный путь процесса и владелец нужны локально для защиты; в отчёт их не включают.
- Замеры и запросы хранятся только в памяти; после перезапуска старые запросы недействительны.
- Сервер и подтверждения слушают только `127.0.0.1`. Панель подтверждения на отдельном
  порту 8798 проверяет адрес клиента, Host, Origin, CSRF и запрещает iframe.
- Не пробрасывайте порт 8798 и не публикуйте порт 8797 через общий туннель: публичная
  авторизация не реализована. Подключайте только через поддерживаемый частный туннель.
- При вызове через ChatGPT показатели процессов передаются в ваш чат для анализа.
- Локальная панель раз в 5 секунд проверяет наличие запросов закрытия; повторную диагностику
  автоматически не запускает.

## Проверки

```sh
npm run check
npm test
npm run verify
node scripts/verify-installed.mjs
```

`verify` поднимает сервер на тестовых портах, делает настоящий замер и проверяет
обнаружение/вызов четырёх MCP-инструментов, ресурс интерфейса, исключение приватных полей
и отклонение запрещённого закрытия. Диагностические артефакты остаются только локально в
`artifacts/` и не входят в переносимый архив.

`verify-installed.mjs` проверяет установленный экземпляр: обнаружение инструментов
через app-server Codex, затем `diagnose_computer`, `show_diagnosis` и ресурс панели через
тот же stdio command, который разрешил Codex. Модель не запускается, чат не создаётся,
инструменты закрытия не вызываются. Независимый тест использует порты 18977/18978
через временные параметры запуска, не меняя пользовательский config.toml.

`scripts/widget-preview.mjs` — отдельный тестовый MCP Apps контейнер на порту 19198.
Для него нужен сервер на 19097/19098. Контейнер загружает настоящий ресурс MCP в
изолированный iframe; его backend разрешает только diagnose/show. Это не проверка
нативного host чата. Сообщения ошибок, отмены и неполных данных в нём синтетические.

Тесты закрытия используют подставные процессы и один дочерний процесс, созданный самим
тестом. Процессы пользователя при проверках не завершаются. Windows API проверяется
подставным WinAPI; это не заменяет реальный запуск в Windows.

Текущее состояние результатов — в `VALIDATION.md`.

## Структура

```text
agent/          сбор показателей, политика защиты и локальный IPC
server/         MCP и отдельная панель подтверждения
public/         интерфейс в локальном браузере и внутри ChatGPT
skills/         инструкция для модели
scripts/        подготовка окружения и проверки
tests/          проверки данных и границ остановки
plugin.json     portable manifest
mcp.json        локальный stdio MCP
```

Модель и OpenAI API внутри агента не запускаются: объяснение в чате делает сам ChatGPT.
Сбор показателей основан на [psutil API](https://psutil.io/api/); зависимость закреплена
на версии 7.2.2 для воспроизводимой установки.
